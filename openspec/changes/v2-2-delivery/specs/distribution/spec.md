## Purpose
How the agent process is installed into a consumer project, how it is updated there, what
footprint it leaves, and how a project extends it without forking it.

## ADDED Requirements

### Requirement: Single source written once as Agent Skills
This repository SHALL be the single source of the process. Process procedures SHALL be
written once as Agent Skills (`SKILL.md` plus a `scripts/` directory inside the skill), the
format both Claude Code and Codex read.

#### Scenario: One skill directory serves both agents
- **WHEN** a skill is changed in this repository
- **THEN** both the Claude Code plugin and the Codex skill install deliver the same directory

### Requirement: Three native delivery channels
The process SHALL be delivered through exactly three native channels: a Claude Code plugin
(marketplace = this repository; skills, the `architect-reviewer` agent, hooks resolved from
`${CLAUDE_PLUGIN_ROOT}`, rules), Codex skills (the same skill directories, each linked at
`$CODEX_HOME/skills/<skill>/` from an updateable checkout), and reusable workflows pinned
`@v2` (CI gates; Dependabot `github-actions` opens the bump PR). OpenSpec is a pinned
dependency (`npx @fission-ai/openspec@<version>`), not a channel.

#### Scenario: Update is a native command
- **WHEN** a new process version is published
- **THEN** a consumer updates with `/plugin marketplace update`, `git pull` of the checkout and a Dependabot PR, with no other step

### Requirement: Consumer footprint created by init
`/agent-process:init` SHALL create the whole consumer footprint: `.github/workflows/agent-process.yml`
(~15 lines), `AGENTS.md` (pointer to the skills, the project's `ci_check` command, its
test-runner command), the pre-push git hook, the ruleset applied once, a repository variable
with the Project number, and `openspec init --tools claude,codex` with this process's
`config.yaml` and schema. Process files SHALL NOT be copied into the consumer.

#### Scenario: Fresh repository
- **WHEN** `init` runs in a repository without the process
- **THEN** every file above exists, the ruleset is active, and no other file was created

### Requirement: Scripts run from where they are delivered
Scripts SHALL run from the skill directory when an agent runs them and from a checkout of
this repository inside the reusable workflow when CI runs them.

#### Scenario: CI run
- **WHEN** the reusable workflow runs a process script
- **THEN** the script comes from the checkout of this repository at the pinned tag, not from the consumer

### Requirement: Consumers extend beside the process
A consumer SHALL extend the process beside it: its own workflows, `ci_check`, rules, skills
and `config.yaml` context under its own paths. The footprint above is process-owned and
`init` MAY rewrite it (an existing `AGENTS.md` is appended to and an existing pre-push hook
is chained, never replaced); files
generated by `openspec init` are owned by OpenSpec (`openspec update`); the process SHALL
NOT edit any other consumer file, and a consumer SHALL NOT need to edit process files.

#### Scenario: Re-running init on an established repository
- **WHEN** `init` runs where the footprint already exists
- **THEN** footprint files are rewritten, `AGENTS.md` and the pre-push hook keep their consumer content, and no other file changes

### Requirement: Update is replacement, never a merge
Updating SHALL be replacement: plugin update, `git pull`, tag bump, `openspec update`. Any
per-consumer value SHALL live in a repository variable, `AGENTS.md` or `config.yaml`
context, never in a templated process file.

#### Scenario: Consumer-specific value survives update
- **WHEN** the process is updated in a consumer
- **THEN** no three-way merge is needed and the consumer's values are unchanged

### Requirement: This repository dogfoods its own plugin
This repository SHALL install its own plugin from a local marketplace so that every process
change is exercised here before a consumer sees it.

#### Scenario: Process change
- **WHEN** a skill or hook changes in this repository
- **THEN** the change is exercised by this repository's own sessions before release

### Requirement: No sync mechanism
The process SHALL NOT use Copier, cruft, git subtree or a sync script, SHALL NOT be a pip
package, and SHALL NOT be a live dependency (submodule, fetch at session start).

#### Scenario: Repository inventory
- **WHEN** the repository is inspected
- **THEN** no template mirror, copier configuration or sync script exists
