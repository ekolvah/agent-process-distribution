## Context

Both carriers reach the portable procedure through the `tasks` rule of `openspec/config.yaml`,
which points at `skills/agent-process/SKILL.md#tasks` (task, architect-review and delivery
procedures). `.claude/commands/opsx/*` and `.claude|.agents/skills/openspec-*` are generated by
`openspec init` and are overwritten on update.

## Goals / Non-Goals

**Goals:** the explanation happens on every propose and apply run without a prompt.

**Non-Goals:** checking the explanation's content or presence by a script (issue: out of scope).

## Decisions

- **Hook in the shared skill, one sentence per section.** `## Architect review` gets the
  planning step after `Planned`; `## Delivery` gets the implementation step at its stop.
  Alternative: edit the generated `/opsx:propose` and `/opsx:apply` commands — rejected, an
  `openspec update` overwrites them and Codex would need a second copy.
- **Name the outcome, not the tool.** "A page linked in the final message, or the explanation
  in that message when the carrier cannot publish a page." Claude publishes with its `Artifact`
  tool (observed in the proposing session's tool list); Codex writes it in its final message.
  Alternatives: a file in the change directory (archived clutter, nobody reads it in the
  repo) or the PR body (does not exist at planning time; the PR body already carries the report
  and scenario map for reviewers, not the person's plain-words view) — rejected.
- **Planning explanation comes after `Planned`.** It describes the approved-by-review plan, so
  a `rework` round does not produce a stale page.
- **The enforced doc names both steps.** `agent-process.md` stays the enforced contract until
  v2 lands (AGENTS.md), so its §Planning end and delivery step 4 each gain one clause.

## Risks / Trade-offs

- [No check that the step ran] → visible by construction: the person reads the final message
  and sees the link or its absence; a test asserts only that the procedure names the step.
- [A carrier whose page tool is unavailable in one session] → the fallback clause makes the
  final message itself the explanation, never silence.
